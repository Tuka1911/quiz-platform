# ТестКласс

Небольшой адаптивный сайт для создания тестов с учительскими и ученическими аккаунтами. Учитель задаёт название, вопросы и время, сохраняет черновик и открывает доступ. Ученик видит список тестов и начинает только открытые; таймер завершает попытку, а ответы сохраняются в Supabase по мере выбора. На тест даётся не более двух попыток.

## Подключение Supabase

1. Создай проект в [Supabase](https://supabase.com/).
2. В Supabase открой **SQL Editor**, вставь `supabase/schema.sql` и выполни скрипт. Если основная схема уже установлена, вместо этого выполни `supabase/upgrade_student_test_flow.sql`.
3. В **Project Settings → API Keys** скопируй Project URL и anon/public (publishable) key в `config.js`. Secret/service role key для сайта не используй.
4. В **Authentication → URL Configuration** добавь адрес сайта в Site URL и Redirect URLs.
5. В **Authentication → Providers → Email** включи Email. Для локальной проверки можно временно выключить подтверждение email; перед реальным запуском включи его обратно.
6. Для GitHub Pages создай публичный репозиторий `quiz-platform`, загрузи файлы этой папки в ветку `main`, затем в репозитории открой **Settings → Pages** и выбери **Deploy from a branch → main → /(root) → Save**. Через несколько минут сайт будет доступен по адресу `https://tuka1911.github.io/quiz-platform/`.
7. В Supabase открой **Authentication → URL Configuration**. Укажи `https://tuka1911.github.io/quiz-platform/` как **Site URL** и добавь этот же адрес в **Redirect URLs**. Для локальной разработки оставь также адрес localhost в Redirect URLs.
8. Создай учётную запись учителя обычной регистрацией. Затем в Supabase SQL Editor выполни запрос, подставив UUID пользователя из **Authentication → Users**:

   ```sql
   update public.profiles
   set role = 'teacher'
   where id = 'UUID-УЧИТЕЛЯ';
   ```

   Все новые аккаунты по умолчанию получают роль ученика. Повысить роль можно только из доверенной консоли Supabase.

## Запуск для локальной проверки

Открой `index.html` через локальный веб-сервер (не через `file://`), например VS Code Live Server. Веб-сервер проекта не обязателен: API и база данных размещаются в Supabase.

## Важные ограничения

- В браузер помещай только Supabase anon/public key. **Никогда** не добавляй `service_role` key, пароль базы данных или ключи администратора.
- RLS ограничивает прямой доступ; ученик не может прочитать таблицу вопросов напрямую. Список тестов и вопросы выдаются через RPC без `correct_index`, а ответы сохраняются и проверяются в базе. Сервер прекращает принимать изменения ответов по истечении времени.
- Первая потеря фокуса фиксируется как предупреждение. Вторая закрывает текущую попытку и учитывается в лимите из двух. В обычном браузере нельзя гарантированно запретить Alt-Tab, другое приложение, отключение сети или изменение DevTools; события фокуса могут быть ложным срабатыванием. Не используй это как единственное доказательство списывания или для критически важных экзаменов.
- Результаты видит учитель-создатель теста. Таймер показывается в браузере, а дедлайн ответов проверяет база данных; для проведения критически важных экзаменов всё равно нужен отдельный надзор. В MVP нет перемешивания вопросов, импорта тестов, восстановления активной попытки после перезагрузки или администрирования классов.
